# 单局玩法与场景创新框架

## 1. 拆解核心

研究玩法时先回答：

| 维度 | 必须明确的内容 |
| --- | --- |
| 输入 | 局前选择与费用；局中是否只有揭示/播放控制 |
| 规则 | 何种事件发生、如何判断、如何计算，不以“类似某游戏”代替 |
| 结果 | 单局最终结果与中间事件的关系 |
| 状态 | 只在本次事件、整局或特殊阶段保留什么 |
| 关注对象 | 玩家是在看符号、位置、累计值、转换链、角色动作还是终点 |
| 信息 | 每次变化告诉玩家什么，哪些元素只是装饰 |
| 结束 | 正常结束、特殊延长、上限截断与总计 |
| 差异 | 去掉主题后，与参考机制还有哪些实质区别 |

简单操作可以配合丰富而清楚的观察状态。不要为了“有策略”加入不影响结果的伪选择。

## 2. 同质化原因的证据等级

- 平台结果结构限制设计空间：有官方依据，但不代表只允许老虎机或级联。
- SDK 提供常见结算与局内状态工具：有官方依据，但不能推出复用模板更容易过审。
- 高波动更受某些人偏好：需要分群数据，不认定所有 Stake 用户都如此。
- 开发成本、熟悉度、流量集中和成功模仿：合理产业假设，需数据验证。
- 工作室数量、游戏总数及 REDAGE 等具体评价：本轮未核实，不能写成既定结论。

## 3. 创新可以发生在哪些层面

| 层面 | 设计方向 | 必须检查 |
| --- | --- | --- |
| 事件结构 | 转换、扩展、传播、收集、结算顺序发生变化 | 同一事件的顺序是否改变计算，优先级是否明确 |
| 空间关系 | 邻接、区域覆盖、路径、方向、位置状态 | 胜负规则是否容易识别，状态是否局末重置 |
| 角色关系 | 角色承担收集、转换或演示功能 | 角色行为与实际规则是否对应 |
| 局内阶段 | 一局内进入机制不同的阶段 | 阶段改变规则而非仅换背景，是否有限终止 |
| 观察体验 | 区分即时回应、过程信息和最终揭晓 | 不把演出呈现成实时决定随机结果 |
| 主题表达 | 主题帮助解释相同机制，或产生新的合法规则 | 只是换皮时如实标注，不能冒称核心创新 |

不要求所有方案都创新数学；主题表现创新与规则创新分别说明。但单靠换素材不应承诺满足 Engine 原创性审核。

## 4. 场景映射

先写“机制动词”，再找能解释它的场景动作。

例如同局标记保留可以表达为金属受热、遗迹符文点亮或线路通电。若规则完全相同，只是表达变化；若通电还按明确邻接规则传播，则属于规则扩展，需要重新定义计算与结果事件。

每个候选交付：
- 一句话体验与玩家关注对象。
- 核心规则、局内状态、结束条件。
- 相对参考的改变及玩家能感受到的差异。
- 场景如何解释变化。
- 最小素材代价、实现难点、验证假设。

## 5. 反馈与情绪

把一次操作拆为：输入确认→结果相关信息出现→合法状态变化→最终结算→返回可开始状态。不是每个游戏都需要悬念延长。

- 输入确认及时，但不承诺未经测量的毫秒阈值。
- 多个反馈同时出现时定义视觉主次，重要数值保持可读。
- 音效对应事件含义和真实结果；避免普通反馈掩盖最终收益。
- 连锁须有真实规则支持，不能用无意义等待延长过程。
- 可跳过动画时快速到达同一结算状态，不漏掉必要信息。
- 移动端、静音、减弱动态效果时仍能理解规则与结算。

文献支持声音和呈现会影响部分体验；不支持“刺激越强越好”，也不证明更高重复次数代表更喜欢。

## 6. 数学体验

把长期期望、返还频率、净盈利频率、分位数、方差、特殊事件频率、最高结果概率分别说明。相同 RTP 可以对应不同分布；不能从最高倍率推导波动，更不能从短期试玩保证长期返还。

对比模式时统一成本基准。描述收益时写明以基础单位还是实际模式成本为分母。状态变化只作用于当前完整结果，不能因历史输赢改变下一局。
