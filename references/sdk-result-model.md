# SDK 结果模型与策划映射

核对日期：2026-11-23。用于把策划规则映射到官方 SDK 及接入模型。版本字段与接口返回名须以具体项目为准，不直接拿概念图当作可调用代码。

## 核心概念

| 概念 | 在模型中的职责 | 对策划的要求 |
| --- | --- | --- |
| GameConfig | 游戏配置入口 | 将盘面、对象、支付规则等映射到已确认的配置能力 |
| BetMode | 独立模式及其成本、数学配置 | 局前选模式与局中事件分开，写明实际成本 |
| Distribution / criteria | 生成模拟结果时的条件分类 | 区分生成配额与最终上线抽取概率 |
| GameState | 生成结果过程中使用的局内状态 | 明确初始值、更新、特殊阶段与重置 |
| Book | 一次已生成完整结果的记录 | 可含多次滚落、特殊旋转等事件，不能只写一个最终奖额 |
| events | Book 中有序的结果事件 | 每个关键规则变化均有可验证数据供前端表现 |
| payoutMultiplier | Book 的最终支付倍率字段 | 使用平台单位，区分实际模式成本与净收益 |
| Lookup table | 为结果记录对应权重与支付信息 | 最终概率来自相应权重，不是默认等概率 |
| index.json | 描述发布模式及对应文件 | 模式、结果与权重资料需一致 |
| RGS | 平台服务端选择结果并处理相关接入 | 前端接收权威结果，不自行决定收益 |

## 两条流程

制作阶段：已确认的 SDK 规则与配置→生成模拟 Book 集合→权重处理与验证→发布模式及对应文件。

运行阶段：玩家选择模式并发起请求→RGS 按模式对应权重选择结果→客户端读取结果事件→依规则表现、汇总及完成本局。钱包与结算时点必须按当前接口处理，不能用此概念流程替代实际调用规范。

Book 可理解为一次完整结果的“事件记录”，不是跨局存档、故事章节或单个动画。模拟时生成多种记录；运行时抽中其中一个，前端表现该记录。Book 内有变化与跨 Book 无玩法继承不矛盾。

## 常见误用

- 免费旋转中的每次转动不自动成为独立 Book；它们可属于同一次启动对应的完整结果。
- Distribution 的生成配额不直接等于发布后触发率；最终结果权重可能经过优化。
- 优化权重不代表改变一个既定 Book 的事件或支付；新规则或新结果通常需要重新生成并核对文件。
- 前端可设计原创表现，但不能临时随机生成会改变结算含义的符号、倍率或分支。
- SDK 输出 Book 不等于平台已验证玩法吸引力，也不代表开发者无需配置、模拟或核验数学。

## 策划必须交付的映射

每个完整方案补充“模式→本局开始/结束→代表性 Book 路径→事件→反馈→素材”的对应。设计阶段可先用自然语言描述代表性路径，明确它是规划示例，不是假装已经由 SDK 生成或获平台验证的 Book。

每种代表性路径说明：模式与成本、关键局内状态、事件顺序、支付归属和最终总计。采用具体事件名或字段时标明官方已有、项目映射或尚待核实；在严格复用要求下，不把自定义字段当作既有官方能力。
