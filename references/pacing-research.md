# 单局结果呈现：研究与定时方法

核对日期：2026-11-23。问题是如何兼顾结果理解、操作响应和重复体验，不是寻找所有游戏共用的秒数。

## 已取得的证据

### 官方实现：分层播放，而非统一局长

已读取 Stake 官方 Web SDK 本地检出，提交 `1843d60cedb94b390e641b563f32ad64353bec5e`，remote 为 `https://github.com/engineio/web-sdk.git`。

- [createEnhanceBoardSpin.ts](https://github.com/engineio/web-sdk/blob/1843d60cedb94b390e641b563f32ad64353bec5e/packages/utils-slots/src/createEnhanceBoardSpin.ts)：普通与 Turbo 分别选择 normal/fast；anticipation 另有 anticipated 分支；各列并行播放。说明播放逻辑按状态区分，不能推出完整一局的固定秒数。
- [ButtonTurbo.svelte](https://github.com/engineio/web-sdk/blob/1843d60cedb94b390e641b563f32ad64353bec5e/packages/components-ui-pixi/src/components/ButtonTurbo.svelte)：区分持久 Turbo 与 stopButtonClick 触发的临时 Turbo。SDK 有能力不代表所有地区或游戏均可启用。
- [lines 参数](https://github.com/engineio/web-sdk/blob/1843d60cedb94b390e641b563f32ad64353bec5e/apps/lines/src/game/constants.ts) 与 [cluster 参数](https://github.com/engineio/web-sdk/blob/1843d60cedb94b390e641b563f32ad64353bec5e/apps/cluster/src/game/constants.ts)：快速配置既调整运动速度，也缩小回弹或移除符号错峰。不能将内部速度参数当秒数，或据此假称线上游戏已实测。

Stake.us 官方 [Snakes](https://stake.us/casino/games/snakes?c=variance) 和 [Packs](https://stake.us/casino/games/packs?c=variance) 页面检索文本描述 Instant Play 可移除动画/等待。这只是功能存在的证据：直接打开页面未成功，未试玩、未测时，也不能将 Originals 的能力直接视为 Engine 接口能力。

### 实验：偏好差异不能压成单一最优值

[Worhunsky & Rogers，2018](https://pmc.ncbi.nlm.nih.gov/articles/PMC5991984/)：72 名成年男性规律赌博者，模拟三转轮实验。估计速度偏好横跨不足半秒到超过七秒；超过半数未达到偏好估计收敛标准。较快条件还伴随支出回忆与结果回忆误差。它不能提供现代 Stake 玩家通用最优值，也不能证明更快等于体验更好。论文检索全文可读；另见 [作者机构版本](https://pure.bangor.ac.uk/ws/portalfiles/portal/19880022/2017_Initial_investigation.pdf)。

[Murch 等，2024](https://journals.sagepub.com/doi/10.1177/17470218241239054)：53 名有经验玩家在真实机器上参与实验，正向强化结果后的主动停顿较损失后更长；特殊奖励样本少。研究把机器视听结束后至下一次启动的间隔单独计时。它支持区分玩家主动停顿与系统演出占时，不能把观察到的停顿规定成强制结果展示长度。

### 数字也可能来自地区规则，而非体验优化

[英国 RTS 14](https://www.gamblingcommission.gov.uk/standards/remote-gambling-and-software-technical-standards/rts-14-responsible-product-design) 分别规定 slots 与其他适用 casino 类别的周期要求，并限制加速功能。只能在对应地区、类别与当前条款内使用；法规下限不等于体验最佳值，也不是 Stake 全平台统一规格。具体项目实施时重新核对原文。

## 据此采用的设计判断（不是实验已证实的配方）

1. 区分普通一次揭晓、连续级联/重触发和完整特殊局；先查同机制参考，再决定各路径的呈现预算。默认体验不应充满无信息的重复等待，但更短也可能损害因果识别。
2. 将结果可读、数值确认、装饰尾效和下一次操作分开安排；短局可比较并行/短错峰，复杂局保留有信息的阶段。
3. 普通与快速模式应有明确差别；快速模式不必机械地全局倍速。启用方式受实际 SDK 与市场约束影响。
4. 用户所说“可能几秒”是问题线索，未经确认不是数值需求。不从快速点击、更多局数或更高支出判断呈现已经优秀。

## 从当前玩法推导节奏（策划判断框架）

先识别玩家每个时刻在等待什么：外部响应、理解变化、期待揭晓，还是仅等待装饰结束。外部等待如实反馈，不用假进度或无结果依据的悬念填补。

| 设计因素 | 要判断的问题 | 可采用的编排与取舍 |
| --- | --- | --- |
| 机制与因果 | 本阶段新增什么规则信息？需先看见什么才能理解下一步？ | 关键触发与结果按因果先后展示；同批独立对象可并行，不能压掉来源与归属 |
| 信息与注意 | 同时要辨认多少位置、数值或状态？ | 分组、聚焦、保留最终盘面；过快看漏时先改善可读性，再判断是否加时 |
| 场景与材质 | 哪个动作能解释规则或形成记忆点？ | 保留扫描命中、机械落锁等关键锚点；可省略写实搬运路程和重复前摇 |
| 事件重要性 | 是普通完成、新规则变化，还是本局特色高潮？ | 按真实意义分配强调；无新信息的阶段不因多次重复就逐次延长 |
| 重复频率与熟悉度 | 初看需要解释什么？熟悉后哪些内容已可预测？ | 教学与常规播放分开；重复阶段可缩短、合并装饰或错峰，不自动删除业务事件 |
| 输入与收尾 | 结果何时足够清楚？还有什么必须阻塞下一操作？ | 明确业务完成条件，装饰尾效尽量不阻塞；根据平台能力定义揭晓、跳过或等待的点击反馈 |

这些因素不套用任意分值加总成秒数。用它们说明每段时间的用途，再结合参考形成项目候选。紧凑不要求所有阶段等快：短确认、有效铺垫、明确接触、适量结果阅读可形成节奏变化。

建议的交付字段：路径/阶段、玩家需理解的信息、场景动作及保留理由、串行/并行关系、候选时长范围与依据、输入状态、重复/快速呈现策略。简单项目可写成简短说明，不强制大表。

### 对“耐心”的可观察检查

- 等待偏长的信号：玩家已正确读懂却反复尝试继续；主动指出某段重复或无事发生。跳过率或连续点击只能定位疑点，不能单独证明不耐烦。
- 呈现偏快的信号：无法指出触发来源、读错最终数值、把两个事件当成一个，或还没看清就被下一步替换。
- 调整时先定位原因：删无信息停顿、压缩重复、并行独立对象、突出关键变化，必要时增加阅读窗口；不是统一把动画全部加速。
- 对同一合法结果比较不同编排，分别记录初次与熟悉后的理解、等待感、控制感和特色记忆。没有真人观察时报告设计判断，不声称已证明不会失去耐心。

例如本项目的声呐流程：初次扫描建立规则与空间认识；重复空扫描可压缩声波与停顿；同批发现可成组出现；关键落锁保留清晰确认；回收总数明确后，装饰牵引不必逐件串行阻塞。此例只说明推导方式，不规定所有探测游戏采用同一局长或改变 Book 内真实扫描次数。

## 确定项目时长的方法

- 按同机制选择可访问的官方试玩或已授权录像；记录游戏版本、日期、设备、地区、模式。不能把宣传剪辑、不同机制或不同速度档混成平均数。
- 每个有效样本记录：输入时刻、结果返回、首次可读、所有收益相关变化可解释、下局可启动、装饰结束。另记用户实际启动下一局的时刻，区分主动停顿。
- 按无奖励、普通奖励、多阶段、特殊结果分组；保留每局原始计时、样本数和计时精度。先看分布与范围，样本不足不声称总体 P95 或行业标准。
- 用同一合法 Book 比较少量有依据的节奏候选，固定结果、输入方式与无关视觉参数；观察结果复述正确率、被忽略/重复的点击、主动跳过、等待感和操作感。初看与熟悉后分别观察。
- 输出“参考实测 → 信息结构差异 → 本项目候选范围 → 验证结果/取舍”。数据不足时明确缺口；不凭研究中的某个实验速度直接指定本项目最佳秒数。

当前完成了官方实现核对与文献研究；尚未完成线上竞品计时或目标玩家比较，因此本记录不提供宣称已验证的最佳秒数。
