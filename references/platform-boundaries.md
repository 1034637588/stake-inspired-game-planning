# 平台与单局状态边界

核对日期：2026-11-23。平台文档会变化，在具体立项和提交前重新查阅官方资料。用户对本技能提出的单局独立要求始终适用；其他平台的能力不能默认为 Engine 能力。

## 官方依据

- [Engine FAQ](https://stake-engine.com/docs/faq)：下注时结果固定，玩家局中决策不能改变它；不支持局中主动兑现。审核关注整体品质及原创性，近似换皮可能被拒。已在其他赌场或供应商发行的游戏不能直接作为新游戏提交。活跃游戏数学通常锁定，仅确认缺陷修复例外。这里仅列决策相关摘要，具体提交重查原文。
- [Math SDK](https://stake-engine.com/docs/math)：发布时准备结果库及选择权重，服务端选择结果供前端呈现，不能将结果理解为浏览器现场计算。
- [Events](https://stake-engine.com/docs/math/game-state-structure/events)：事件描述盘面、免费旋转计数、倍率与特殊动作等，供前端展示。
- [Game configuration](https://stake-engine.com/docs/math/game-state-structure/setup/configs)：区分基础/特殊阶段，支持特殊旋转触发和再触发规则。这是局内复杂性可行的依据。
- [Math file format](https://stake-engine.com/docs/math/math-file-format)：SDK 不是强制工具，但发布格式必须满足平台要求；文件间收益必须一致。不要把 end-round 调用写死成通用规则，应按当前模式配置及接口规范处理。

以上源可说明能力与约束，不能作为审核或商业效果保证。搜索索引可读但动态原页无法展开时，标记核对方式；没有实际检查的条目不能写成已核实。

## 用户指定的 SDK 使用约束

平台允许自定义实现与本项目允许自定义实现是两回事：即使官方格式接受不用 SDK 的发布文件，本技能仍必须采用官方 SDK 和接入能力。官方可扩展性不能被当作自行发明收益算法已获授权。

机制分为“直接复用”“官方配置/已支持组件组合”“待核实”“不支持”。前两类才可进入推荐可执行方案；组合后的状态生命周期、计算顺序与接入兼容性仍须核对。每项记录具体版本、功能或示例、官方来源与需要配置的内容；未知版本不捏造函数名或参数。

主题、动画和音效可原创，但不得改变结果语义。任何自定义计算或接入扩展需求单独列出，并优先替换为当前官方能力内的方案。

## 单局边界

一次启动/下注请求所对应的完整结果，可能包括基础事件、多次消除、免费旋转、再触发及最终结算。画面上的“一次旋转”未必是一局。

状态要分层：

| 类型 | 示例 | 处理原则 |
| --- | --- | --- |
| 事件临时状态 | 一次消除期间的高亮 | 在相应事件结束清理 |
| 局内规则状态 | 当局累计值、锁定格、剩余特殊次数 | 只在规定阶段保留，整局结束归零 |
| 恢复/回放状态 | 已发生事件和播放位置 | 继续同一结果，不能重抽或再次领取 |
| 偏好设置 | 音量、语言、减弱动态效果 | 可保留，但不改变结果或资格 |
| 跨局玩法状态 | 上一局能量、连续失败保底、累计升级 | 与本技能的产品硬约束冲突 |
| 平台外部状态 | 钱包、平台活动与账户系统 | 与本局玩法分开，不假定游戏有权修改 |

“记忆感”必须说明记忆发生在哪个生命周期内。局内越打越强可以表达为同一结果中的阶段增长，不能把增长带入下一局。

## 可行与冲突示例

| 想法 | 判断与处理 |
| --- | --- |
| 本局列车经过多个站点，在终点汇总结算 | 可作为预先确定的事件序列；不能中途择站兑现改变收益 |
| 消除后格位留下本局痕迹 | 可行；写明基础序列/特殊阶段各自何时清理 |
| 点宝箱逐步揭示已经确定的内容 | 只改变揭示顺序或速度；不得声称选哪个箱子影响收益 |
| 手动射击命中决定最终奖额 | 与当前 Engine 固定结果约束冲突；可改为局前模式选择后自动演示，但须说明体验已变化 |
| 凑齐前几局碎片后下一局进入奖励 | 与用户要求的跨局独立冲突 |
| 把上局奖金用于连续翻倍 | 不作为 Engine 兼容设计；不能以多个请求包装成持续赌注 |

不把官方提及的独立付费分步模式当作普遍中途兑现方案。只有用户确实需要、并重新核实完整协议与产品语义后才能单独设计。

## 每个方案的边界卡

写清：启动点；结果确定点；局前选项；局中合法交互；事件序列；状态初始化/更新/清理；总收益；结束条件；中断恢复；下一局起点。初次开始与任何历史之后开始时，同一模式的规则与概率应一致。

## 发行与变更

面向多个平台时先确认发行顺序与相应规则。主题和机制可复用的方法论不等于同一成品可任意上架。将上线后改数学视为平台条件项，不默认支持持续调参。上线前可做无真钱原型对照；上线后的实验需要先判断是否改变数学及平台是否允许。
