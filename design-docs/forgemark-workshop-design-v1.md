# 铸痕工坊 · FORGEMARK

单局游戏策划方案 v1.0 · 2026-11-23

**一句话：同一块模具连续铸造三轮，命中过的格位留下刻度，后来的连片若覆盖这些位置，就按旧刻度提高本次返还。**

交付性质：立项与原型交接文档，非已上线规则。方案复用官方 Math SDK 集群、滚落、位置数值累计和特殊阶段组件；尚未生成本作完整 Book、优化权重或验证 RTP。所有支付表、上限与时间范围均为本作原型建议，不代表官方标准或已验证数学。默认先交付无真钱原型，不据此改变最终可适配平台的范围。

## 1. 产品、场景与范围

玩家是小型机械工坊的铸造师。材料在 5×5 模具中成片熔合，冲压后在**模具位置**留下刻度。新材料会落下，模具上的刻度留下；第二轮、第三轮换一批材料，继续利用同一块模具。

核心关注对象从“出了什么符号”转到“这一片覆盖了哪些旧刻度”。招牌瞬间是新连片亮起时，下面的旧刻度依次接入，合成一个清楚的本次计算式；随后一次短促冲压确认结果。

- 目标体验：规则易读、过程紧凑、位置变化有记忆点。不是手速或选格策略游戏。
- 目标平台：Stake Engine 候选；其他平台另核接入与发行条件。不承诺原创性审核通过。
- 设备假设：移动端竖屏优先，桌面端居中盘面；以 390×844 与 1440×900 为首轮布局检查尺寸。
- 最小范围：一个成本模式、一块模具、三轮材料、四种可支付材料；不做买奖励、跨局等级、任务或追加付费。
- 制作预算假设：1 名客户端、1 名数学/结果数据工程、1 名美术动效及共享音频/测试支持。先做程序绘制原型，再估正式排期；这里不承诺工期。

## 3. 玩家规则与计算口径

### 3.1 可直接用于规则页的表述

1. 每次启动购买一组三轮铸造，三轮属于同一局。
2. 每轮中，5 个及以上同类材料上下左右相连形成支付连片；斜向不连接。
3. 连片支付后材料移除，上方材料下落并补充，继续检查；没有支付连片时进入下一轮。
4. 参与支付的格位会留下刻度：首次变为 1，之后每次命中加 1，单格最多 4。
5. 本次连片先使用**命中前**覆盖格位的刻度之和计算，再更新这些格位；总和为 0 时按 1 计算。
6. 刻度跨本组三轮保留，整局结束清空。没有额外奖励轮或追加收费。
7. 点击与快速揭晓只影响播放，不改变本局内容及返还。

### 3.2 支付表原型配置

基础金额单位记为 `b`，实际模式成本 `C=b`。下表为每个集群的基础返还倍数 `q`，未经过 RTP 优化。

| 材料 | 形状与识别 | 5–6 个 | 7–9 个 | 10–14 个 | 15–25 个 |
| --- | --- | ---: | ---: | ---: | ---: |
| A 铜片 | 方片，铜色 | 0.10 | 0.20 | 0.40 | 0.80 |
| B 钢环 | 圆环，蓝灰 | 0.15 | 0.30 | 0.60 | 1.20 |
| C 棱晶 | 三角，青绿 | 0.20 | 0.40 | 0.80 | 1.60 |
| D 金印 | 菱形，金色 | 0.30 | 0.60 | 1.20 | 2.40 |

对支付集群 `G`：

`M(G)=max(1, Σ p[x,y])`，`集群返还=b×q(材料,数量)×M(G)`。

全局倍率固定为 1。**求和对象是位置刻度，不是材料面值；不是每格各乘一次，不是刻度相乘。** 单格 0 表示未激活；1 表示已激活。未激活五格首次命中仍为 ×1；五个刻度为 1 的格位再次一起命中则为 ×5。

同盘所有集群先使用同一份旧刻度快照求值，再一并把参与格位更新为 `min(p+1,4)`。本作无 Wild，不同集群不会共享格位。刻度固定在模具坐标上，不随材料下落。

### 3.3 规则优先级、入口与结束

**入口实施方式：**沿用官方强制特殊阶段分布，配置一个无基础支付、含固定入口印记的引导盘，触发 3 轮特殊阶段；不开发“前端直接跳过数学入口”的旁路。入口仅表达“本组开始”，不表现为意外中奖或额外获赠。BR 条带/强制条件需验证入口数量及无基础支付，失败则不得把不符条件的 Book 放入结果库。

入口印记使用 S；仅入口使用，FR 条带没有 S。保持非空的合法阶段触发表，避免 SDK 对空表取最小值的问题。所有允许的入口印记数量统一映射为 3 轮。普通界面称“三轮铸造”，规则说明这就是一次启动购买的全部内容。

每个支付快照按此顺序：

1. 查找集群，使用旧位置刻度计算原始集群返还。
2. 发出支付及累计事件，检查 SDK 上限。
3. 更新命中格位刻度，发出 `updateGrid`。
4. 未达上限且仍有支付时，移除/落下/补充；否则结束本轮连锁。
5. 三轮完成后按完整 Book 最终金额结束；新局清空所有刻度。

原型总返还上限建议为 `100b`，需在 SDK 的游戏与模式配置保持一致；不是已验证最高可达结果。达到上限时按权威 `wincap`/`finalWin` 显示封顶金额，不展示超过上限的可领取总数。注意当前示例外层仍可能输出剩余轮相关事件，不能假定 `wincap` 自动跳出全部特殊轮；客户端须完整消费实际 Book，并把剩余过程收束为“本组已达上限”，不承诺未执行的提前终止能力。

有限性：固定三轮，无再触发；每个继续滚落的正支付至少 0.10b，加上有限支付上限，正支付循环不会无限推进。上限后的外层仅剩有限轮数。极长但有限的连锁仍可能出现，不以截断 Book 解决时长问题；优化发布权重及压缩呈现分别处理，须保持合法结果语义。

## 4. 一局流程、交互与状态

`待机 → 请求接受 → 入口印记确认 → 第1轮及其滚落 → 第2轮及其滚落 → 第3轮及其滚落 → 最终结果 → 可再次启动`。

| 状态 | 初值/单位 | 更新与范围 | 清理 | 收益相关 |
| --- | --- | --- | --- | --- |
| `roundId` | 平台返回 | 贯穿一次完整 Book | 完成本局后保留历史引用 | 用于幂等与恢复 |
| 铸造轮次 | 0/3 | `updateFreeSpin`，只表示本组内进度 | 新局归零 | 不额外收费 |
| 位置刻度 p | 25 格全 0，范围 0–4 | `updateGrid`，三轮内保留 | 新 Book 清空 | 是 |
| 当前盘面 | 空 | `reveal`、`tumbleBoard` | 新盘替换 | 是 |
| 本次支付 | 0b | 权威支付事件 | 下一快照替换 | 是 |
| 本局累计 | 0b | 权威累计事件，最终与 `finalWin` 一致 | 下一局归零 | 是 |
| 已播放事件索引 | 未开始 | 每事件推进 | 仅随原 Book 恢复 | 否，不重抽 |
| 快速/静音/减弱动态 | 用户偏好 | 表现选项 | 可跨局保留 | 否 |

局前真实选择：成本档与允许的表现设置。仅一个数学模式，没有伪装成策略的温度、选格或敲击力度。忙碌期间主按钮表达“揭晓”或明确等待；收束当前局的点击不得同时购买下一局。失败或超时先确认平台是否已受理，不盲目重发付费请求。恢复读取原结果和状态，不重掷材料；回放不再次结算。

## 5. 可手工复算的规划结果

以下为规则示例，不是已由 SDK 生成的 Book，不代表概率。设 `b=C=1`，总返还为 R，净结果 `R−1`。坐标为玩家可见 `(列,行)`，均从 1 开始；SDK 数据可能含 padding，接入层必须明确转换。

### 5.1 无返还路径

三轮各展示一个无 5 连片的盘面，无滚落、无刻度变化。可用如下盘面作为每轮示意（材料权重并非等概率）：

```
A B C D A
B C D A B
C D A B C
D A B C D
A B C D A
```

R=0，净结果 −1。显示“本组返还 0”，无庆祝性撞击或“差一点就成功”的暗示。

### 5.2 普通路径：有返还但仍净损失

第1轮 A 集群占据 `P={(1,1),(2,1),(3,1),(4,1),(5,1)}`；其余格排布不构成支付集群。

- P 旧刻度全 0：q=0.10、M=1，返还 0.10；P 更新为五个 1。
- 滚落后无新支付；第2、3轮也无支付，刻度保留但不产生独立奖金。
- R=0.10，净结果 −0.90。展示“返还 0.10 / 净结果 −0.90”，不使用盈利庆祝。

### 5.3 特色路径：同一模具位置被回用

以下各快照仅有指定支付集群，未列位置为不形成支付的材料；每次支付后的补充无其他支付。

| 步骤 | 支付集群位置 | 旧刻度和 M | q | 本次返还 | 支付后刻度/累计 |
| --- | --- | ---: | ---: | ---: | --- |
| 第1轮 | P 上的 A×5 | 0→最低1 | 0.10 | 0.10 | P 均1；累计0.10 |
| 第2轮 | P 上的 B×5 | 5 | 0.15 | 0.75 | P 均2；累计0.85 |
| 第3轮 | Q 上的 C×5 | 2+2+2+0+0=6 | 0.20 | 1.20 | Q 内前三格3、后两格1；累计2.05 |

`Q={(1,1),(2,1),(3,1),(3,2),(3,3)}` 是上下左右连通的 L 形，确实只覆盖 P 的三个旧位置。

R=2.05，净结果 +1.05。第三轮显示 `基础0.20 × 旧刻度合计6 = 本次1.20`，然后再将相关刻度更新。不是先把前三格升级为 3 再结算。

### 5.4 同轮滚落与刻度上限

同一轮先 A×5 命中全新 P，返还0.10；补充后 B×5 再次占据 P，使用五个1得到0.75。两次属于**同一轮**，不是消耗两轮。其后再无支付则进入下一轮。

若某快照 P 五格旧值均为4，D×5 的原始返还为 `0.30×20=6`；支付后仍均为4。假设此前累计98，则本局权威总返还封顶100；该步实际新增可计入为2。原始计算6与封顶新增2必须区分，客户端不将6再次加到100上。该状态是否可由本作条带实际达到，须由生成器验证。

## 6. Book、事件与数学交接

仅一个 BetMode：工作名 `forge`，实际成本1b。一次 Book 含入口与完整三轮。配置使用官方集群示例及官方分布条件，不把每轮拆为独立付费请求。

代表性事件链（简写，实际保留 SDK 发出的全部累计与结束事件）：

`入口reveal → freeSpinTrigger(totalFs=3) → [updateFreeSpin → reveal → updateGrid(当前刻度) → winInfo/updateTumbleWin → updateGrid(新刻度) → tumbleBoard → …]×3 → freeSpinEnd → finalWin`。

- `reveal`、`winInfo`、`updateTumbleWin`、`tumbleBoard`、`updateFreeSpin`、`freeSpinTrigger`、`freeSpinEnd`、`wincap`、`finalWin` 是已核官方事件。
- `updateGrid` 是官方**集群示例**提供的事件，不冒称所有游戏通用字段；使用 `gridMultipliers`。
- 后文 E01–E08 是策划分镜 ID，不是新加到收益协议里的事件类型。
- `winInfo` 的集群位置与 `meta.clusterMult`、`winWithoutMult` 可用于解释计算；上限情况以权威累计/最终事件为准。
- `setWin`、`setTotalWin` 等若在实际 Book 出现，必须消费；本节不是删减事件的白名单。

## 7. 节奏推导与原型候选

### 7.1 等待为什么存在

本作每轮最多需要理解两层信息：材料形成连片；该连片覆盖的旧刻度参与计算。第一层沿用直观连片高亮，第二层是本作应保留的焦点。

- 材料落下：可并行，主要提供盘面与机械质量感，不做逐格点亮。
- 旧刻度接入：只高亮当前集群下方相关刻度，保留其和与基础支付。无需逐格报数。
- 冲压：短促接触确认，声音与印痕同步；不等待完整升降机往返。
- 无支付轮：盘面稳定并完成检查后切换，不能再播放长“搜索失败”。
- 后续滚落：缩短重复前摇，保留每次真实支付、位置和累计更新；不能合并成一个来源不明的大数字。
- 三轮间：保留模具，材料换批；用“第2/3轮”短标识，避免整屏换场。
- 最终返还：不再播放逐枚金币回收。稳定数字留在结果区，允许之后主动阅读。

### 7.2 时间预算：设计假设，不是最佳时长

依据是本作的信息层次及官方正常/快速编排能力，**没有线上同类竞品计时或真人测试数据**。下列值为首轮原型候选；平台请求、钱包完成及法定最小周期另计。动画从权威结果可用开始，所有路径仍只有一次启动请求。

| 分段 | 标准候选 | 快速候选 | 执行关系与理由 |
| --- | --- | --- | --- |
| 入口压印 | 0.20–0.30s | 0.10–0.18s | 仅确认固定三轮组，不当稀有事件庆祝 |
| 每轮落料及可读检查 | 0.40–0.55s | 0.25–0.35s | 所有格并行；空轮也保留看到最终盘面的机会 |
| 每次支付额外阅读/冲压 | 0.30–0.45s | 0.20–0.30s | 先显示旧刻度公式，再接触；刻度更新与冲压尾段重叠 |
| 每次滚落补充及检查 | 0.28–0.40s | 0.18–0.25s | 支付后顺序发生；不重复入口蓄势 |
| 每次跨轮换批 | 0.12–0.18s | 0.08–0.12s | 两次；短轮次标识，无独立介绍卡 |
| 最终结果强调 | 0.20–0.35s | 0.15–0.25s | 只短强调；数字之后持续可读 |

令 K 为整组三轮支付快照数；未达上限时通常每个支付后都有一次补充检查。于是标准预计 `入口 + 3×落料 + 2×换批 + K×(支付+补充) + 结果强调`，并行元素不重复相加。

| 代表性整局路径 | 标准呈现预算 | 快速呈现预算 | 结果首次完整可读 / 可再次启动 |
| --- | --- | --- | --- |
| 三轮皆无支付 K=0 | 1.84–2.66s | 1.16–1.72s | 末轮检查结束时明确为0；短强调结束且平台允许后可再次启动 |
| 一次支付 K=1 | 2.42–3.51s | 1.54–2.27s | 支付累计先增量可读；三轮结束才明确完整总额 |
| 示例位置回用 K=3 | 3.58–5.21s | 2.30–3.37s | 每步给依据；最终值在末次真实变化结束后可读 |
| 较长连锁 K=6 | 5.32–7.76s | 3.44–5.02s | 不是上限时长；根据真实Book继续，支持允许的揭晓收束 |

这些较长路径提供更多真实信息，不应把每局都强制拉到它们的时长，也不能为了“普通局必须几秒”压掉刻度来源。若熟悉后觉得重复，先缩短换批和补充空隙；若不能复述倍率来源，先改高亮/公式，再考虑增加阅读窗口。

点击反馈与异步等待：按下立即改变按钮状态；结果未到时展示明确加载状态，不虚构进度。模式支持时，忙碌期间一次“揭晓”收束剩余装饰、按序处理全部事件至一致最终状态；该次输入不自动购买下一局。快速档仍保留因果提示。没有快速档权限时正常呈现，不绕过平台限制。最终数字保持到下一次启动或用户明确离开，不能设置自动一闪而过。

端到端报告应记录：启动时间、结果返回、首次局部支付可读、完整总额可读、平台完成确认、下次输入可接受、装饰结束；不能把网络等待算成必要艺术演出。

## 9. UI 与可读性

主视觉层：材料在上，固定刻度在模具底层；材料移除后刻度可见。刻度只用小数字1–4与短槽线，未激活不画0，避免25个数字同时抢焦点。

- 顶部：本组第几轮/共3轮；不放跨局进度条。
- 盘面：当前支付集群轮廓与相关刻度突出，其他格略降明度；最多一个主公式焦点，同盘多个集群以明细列出而非叠字。
- 底部：本组成本、累计返还、最终净结果；启动/揭晓按钮与声音、快速、减弱动态入口。
- 规则入口：解释旧值先支付、位置固定、三轮同局与局末清空；首次可用一段可关闭示意，之后不强制重复。
- 移动端保持形状、字母/纹样及颜色三重识别；不靠色相区分四材料，不依赖悬停。金额长文本做布局适配，不截掉关键位数。
- 减弱动态：取消镜头偏移、大闪光，保留描边和公式；静音不影响轮次或支付判断。
- 加载/失败/恢复明确区分；无结果不写“铸造成功”。Social Mode、平台语言、回放与术语要求在接入阶段按当前官方规范适配，不新增自有语言切换与平台品牌启动页。

玩家短文案：“旧刻度先参与计算，命中后再加1。”“材料会移动，刻度留在原位。”“三轮属于同一组，下一组重新开始。”不向玩家暴露 Book 或SDK术语。

## 11. 最小原型与验收

### 原型顺序

1. 数据层先输出合法入口、三轮、位置更新、支付和最终金额。复用官方函数；先核明每个坐标的padding转换及计算/更新次序。
2. 程序绘制模具与四材料；以锁定结果提供无返还、净损失返还、跨轮位置回用、同轮滚落、格位上限、总封顶六类路径。
3. 做标准/快速候选，固定相同Book比较；先验证公式与位置读懂，再加冲压与声音。技术演示不得宣称通过听音或真人测试。
4. 完成必要平台认证、恢复与回放后，再决定正式美术制作与数学优化。当前文档不包含程序制作请求。

## 12. 立项风险与决策门槛

- **核心风险：看不懂刻度相加。** 先测试“旧刻度合计”的公式与空间高亮；不能直接用更长演出掩盖解释差。
- **辨识度风险：仍像常见位置倍率集群。** 明确属于结构组合创新；若没有记忆点，不以换主题就宣称成功。
- **节奏风险：固定三轮增加空轮成本。** 首先缩短轮间换批和无支付检查；如仍显冗余，应在立项阶段重新比较三轮与更短配置，重新生成/验证数学，不能由前端临时跳过一轮。
- **数学风险：位置刻度合计可快速放大。** 支付、条带与权重必须整体核算，不能直接沿用示例支付表/回报率。
- **工程风险：封顶与外层轮数语义。** 已指出示例不保证封顶后外层立即退出；以实际Book回归，不臆造现成结束调用。
- **发行风险：地区限制、Social Mode、语言、回放及原创性。** 接入与提交时核当前规范；不保证过审或任意跨平台发行顺序。

建议进入原型的条件：数据路径可闭合；观察者能解释位置累计；普通路径没有冗余等待；标准与快速均保留结果因果。任一条件不成立，先修原型，不扩大奖励系统或正式美术范围。
